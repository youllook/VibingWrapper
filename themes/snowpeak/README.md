# 雪山雲海（snowpeak）

站在台灣高山稜線（玉山／合歡山的感覺）往西北西看：腳下是長著箭竹和玉山圓柏的坡，往前落進雲海；中景是一道前山（雲瀑從它的鞍部翻過來），後面是主峰群——主峰在畫面右側偏中、不對稱的山形（長長的西稜、一個肩、短短的頂稜、東側陡落）——再後面是被大氣透視洗淡的遠山。真正的雲海只出現在穩定的好天氣（高氣壓、逆溫層），所以**雲海上方的天空在每個狀態都是晴的**——Claude 的狀態由雲海和風來演（跟稻田主題一樣，天空永遠晴朗）。真實台北時間，清晨的日照金山是重頭戲；05–09 點有晨霧在雲海上；夜晚有星星、銀河和月光下的雲海。每個 Claude session 是坡上一頂小帳篷（或前山上一盞山屋燈）。

- 入口：`index.html`（WebGL2，全程序式，沒有任何外部函式庫或圖檔，離線可用；2026-10-13 由 Claude 設計，同日第二輪重做山體／雲海／前景／帳篷／暴風雪，第三輪加上會轉向的風、分層的雪、柔邊的雲瀑，第四輪改全解析度＋抗鋸齒，第五輪改成「天空永遠晴、雲海和風演狀態」，不再下雪）
- 測試介面：`window.theme`（也掛 `window.snowpeak`）
- 預覽：`http://127.0.0.1:47321/themes/demo.html?style=snowpeak`

## 狀態 → 參數

每個狀態是一組目標數值，切換時從目前的實際數值平滑轉過去（可中斷，時間依變化量縮放，最長 4 s）。定義在 `index.html` 的 `PARAMS`（範圍）和 `STATES`（目標）。

| 狀態 | 意思 | 雪山的樣子 |
|---|---|---|
| `clear` | 晴：閒置 | 雲海低低地躺在山谷裡，平靜、慢慢漂；早上偶爾有鑽石塵閃一下 |
| `overcast` | 陰：Claude 在想 | 雲海漲起來、開始翻動；前山後面的雲池高過鞍部，**雲瀑**從鞍口溢出、沿山面往下流、越流越薄、被風吹偏；稜線上開始有一點風吹雪 |
| `storm` | 工作：Claude 在跑工具 | 晴天裡的大風：雲海翻騰（流得快，一波一波的雲浪往山谷裡推，前山只剩稜頂露出來）、雲瀑大量傾瀉；**風吹雪**從主峰和各條稜線上被吹成雪煙往下風處拉，也一縷一縷貼著我們腳下的坡掃過（鏡頭前幾顆失焦的雪粒、中景的條紋、前山稜上的細雪） |
| `clearing` | 轉晴：剛做完 | 雲海沉下去、變薄，山頭轉金黃；空氣裡的鑽石塵在陽光下閃 |
| `waiting` | 等你：Claude 在等你回答或批准 | 雲海停住不動、光線暗一點點，同一顆四芒 等你 星（x≈58%、y≈80%，約 2.9 s 一次脈動，跟其他主題同位置同節奏），帳篷燈跟著一起脈動 |

天空上最多只有幾縷很薄的高雲（`highCloud` ≤ 0.16），不會讓光變暗；沒有雷雪、沒有暴風雪天空、沒有從天上落下的雪。

參數：`seaLevel`（前山前面的雲海高度）、`seaBack`（前山後面雲池的高度，高過鞍部就會溢出）、`seaDensity`、`cascade`（雲瀑）、`churn`（雲海翻騰：流速、推進山谷的雲浪）、`highCloud`（高空薄雲）、`spindrift`（風吹雪）、`dust`（鑽石塵）、`skyBrightness`（等你時稍微暗一點）、`warmth`（金光）、`haze`（空氣透視）、`beacon`（等你星）。

## 營地（session）

`state.json` 的 `sessions` 五個位置各對應一個固定的視線方向（`CAMP_SPOTS`，避開左邊桌面圖示那三分之一和 等你 星那一欄）；第一次 bake 完從深度讀回那個方向打到的地面點，所以帳篷永遠坐在坡上。位置 0–2 是前景坡上的登山帳（第五輪重做：低矮扁長的隧道帳，高度約長度的 1/3，外帳拉到地面、三道營柱只在外帳上留下淡淡的稜、前端一個斜斜的前庭和門、四條細細的營繩拉到營釘；在坡面自己的座標裡 ray-march 一個外帳高度場，帳篷貼著地面坡度、稍微嵌進地裡、周圍有接觸陰影；每個位置一種顏色：黃、橘、綠、紅、灰藍，白天低彩度），位置 3–4 是前山上的山屋燈。沒有任何 session 時，位置 0 留一頂跟著天空狀態的帳篷。進出 2.5 s 淡入淡出。

| session 狀態 | 營地 |
|---|---|
| `clear` | 白天幾乎看不出燈，傍晚／夜裡一盞暖燈 |
| `overcast` | 燈亮一點 |
| `storm` | 燈全亮，兩顆頭燈沿著營地上方的小徑走來走去 |
| `clearing` | 燈半亮 |
| `waiting` | 燈跟著 等你 星一起脈動 |

白天外帳的受光面和背光面明顯不同（背光面有一點陽光透過布料），會被地形陰影遮到；黃昏、夜晚、storm 時燈從裡面透出來，帶一點布料的顏色，靠近地面和門最亮、往上淡掉，也照亮周圍幾公尺的地面；飄過帳篷附近的風吹雪會染上暖光。

## 日夜

台北的太陽高度（跟其他主題同一套 `sunAltitude`）。鏡頭面向西北西：日出時太陽在左後方，正面打亮主峰（日照金山、受光面橘粉色、背光面冷藍），前方天空有「維納斯帶」粉色帶壓在藍色地影上；中午太陽在左邊；傍晚在前方落到山後（逆光）。主峰比谷底早幾分鐘被照到（`peakSun`）。晨霧 05–09 點（07 點最濃）只積在雲海上方，不洗掉山頭。夜晚月光當主光、曝光拉 2.4 倍，每個狀態都是星空、銀河、月亮和月光下的雲海（鑽石塵在月光下也會微微閃）。`?day=1`／`?night=1`（齒輪「模式」的日間／夜間）把時鐘固定在 10:30／22:00。

## 畫面配置

- 鏡頭固定在原點、往下俯 0.05 rad、垂直視角 46°；單位是公里，眼高約 3,400 m（雪線大約在眼高附近）
- 左邊三分之一（桌面圖示）：只有平靜的雲海、低矮淡遠的山稜和天空；前景那一側比較暗、比較少石頭與灌叢，風吹雪和鑽石塵也比較稀
- 右上角（HUD）：只有天空
- 主峰的形狀全部在 `MASSIFS`：每條稜線是一串 `[x, z, 稜頂高度]` 的點，加兩側坡度 `s1 / s2`、溝槽深度 `amp`、間距 `sp`。要改構圖改這張表就好（`theme.rebuild()` 會重新 bake）

## 做法

- **山體＝稜線折線**：高度 ＝ 所有稜線段的 smooth max（稜頂高 − 對稜線距離的凹形坡面），所以每座山都有往下延伸到雲海底下的寬山腳，不是浮在霧上的紙板。
- **侵蝕溝槽在稜線自己的座標裡做**（u 沿稜線、d 往下坡）：跨坡方向是週期性的溝槽剖面（尖的刃脊、圓的溝底），會蜿蜒、往下散開、每條深淺不同，再加一組細的；取最高的三條稜線段各算一次、用「高出第四高多少」當權重混合（掉出前三名時權重剛好是 0），所以換段時沒有裂縫；沿稜線的座標在線段兩端夾住不外插（外插會讓相鄰線段的溝槽相位錯開，疊成一格一格的方塊——第五輪修掉的「階梯雪」就是這個），溝槽剖面是圓滑的 cosine（刃脊不再是刀口折線），每條溝的深淺沿稜線平滑變化。細節層級（octave 數）是連續的小數，不會在固定距離跳一階。支稜斜著朝鏡頭，溝槽讀起來是人字形；主峰正面是一道道直落的雪溝。再疊 iq 的「帶導數、陡處衰減」fbm 當岩塊與岩紋。
- **雪看坡度＋高度＋凹凸**：雪線以上、坡度夠緩的面和凹進去的雪溝積雪；刃脊和陡壁是黑色板岩，所以雪的分布就把山形畫出來。遠山只看大形（不然會變成柵欄）。
- **前景**：一面往前落進雲海的坡（約 16°，100 m 外變成 45° 落下去），右邊一個岩丘；有層理的板岩塊（節理裂縫、地衣）、低矮成團的玉山圓柏、箭竹（被風梳過的筆觸、乾黃的尖）。貼圖的高頻依像素大小淡出，不閃、不糊成方塊。
- **Bake 一次，每格只算光與雲**：地形深度只在啟動／改視窗大小時 ray-march 一次；法線（解析式中央差分）、材質、太陽軟陰影、AO存進 G-buffer（3 張 RGBA8 MRT，深度用 sqrt 編碼，近處 2 cm 精度）。太陽移動 0.5° 才重 bake 屬性（不重 march 深度），分成 120 條掃描帶、一格畫一條到後緩衝，畫完再交換，所以不會卡頓。
- **雲海**（第六輪 2026-10-13 重做，原本是單一尺度的 billow 高度場、像棉被／緞面枕頭）：雲頂包絡＝大尺度起伏（~1.8 km）＋花椰菜狀的雲頭（~0.6 km、圓頂平台形，不是 abs() 折出來的摺痕）＋更小的雲頭＋小團，用 domain warp 打散重複，再用一張區域遮罩分出「堆高的雲田」和「平坦的大片」。每像素先往下找到包絡、二分到交點，從交點開始沿視線在薄層裡積分密度（10 步，樣本對齊交點所以沒有色階或顆粒）：Beer–Lambert 消光、powder 項、Henyey–Greenstein 前向散射（對著太陽／月亮的銀邊）、天空環境光從上面來、越深越暗；每一步再往光源方向探一次包絡，被旁邊雲頭擋住的地方是柔和的陰影。頂上有一層約 40 m 的薄紗、邊緣用細 noise 侵蝕成纖維狀，所以雲邊是半透明的；雲裡面有斜穿過層的棉絮狀明暗。山坡進入雲海處有霧裙往上爬。前山後面的雲池（第七輪）是一大片邊緣被打散的區域，不再是窄窄一塊（它的邊緣曾在右邊站成一道直牆）；雲海漲到眼睛高度以上時，水平線以上的視線也會去找雲（原本只追往下的視線，雲頂在水平線被切成一條尺畫的直線），雲頂上限留夠高度不削平雲頭，大雲頭在遠處也保留，所以遠處雲海和山腳交界是起伏、柔和、帶空氣透視的。雲瀑是同一個包絡：鞍部後的雲池溢出、沿前山坡面往下流，在密度裡被撕成順著流向的霧條、越往下越稀。
- **天空**：分析式（天頂／地平線漸層、太陽與光暈、暮光、維納斯帶與地影、幾縷高空薄雲、星星、銀河、月亮），永遠是晴天。
- **風**（`windAt()`）：方向＝三個互不成倍數的慢週期（540／331／197 s，幾分鐘的大漂移）＋一個 fbm noise 的遊走，最多斜到約 70°，偶爾幾乎垂直（雪直直落）；**風速自己獨立遊走**（另一組 noise＋143 s 週期，經過次方曲線：有雪幾乎懸著的停頓、也有拉成長條的猛吹）；陣風的長短（約 2–10 s）和力道也各自慢慢變，陣風時方向再推斜 ~23°。全部是時間的平滑函數（載入時的牆上時間＋場景時間），不會跳。同一個風場推動：風吹雪、雪煙、雲瀑的流速與側偏、雲海與高雲的漂移。`theme.wind` 讀目前的風，`theme.CONFIG.windOffset`（秒）可以把風的時鐘往前撥。
- **風吹雪**（晴天被風吹起來的地面雪，沿用分層粒子＋隨機風場，gl_VertexID 算位置，沒有 CPU 模擬）：鏡頭前 40 顆失焦的大雪粒（軟圓盤）、1,200 顆中景雪粒（橫向的短動態模糊條紋，長度跟風速成正比）、1,400 顆前山稜上的細雪；都貼在畫面下半（我們腳下的坡、前山稜線），跟著風橫向走、陣風時被往上捲、停頓時落回去；**沒有側風就沒有風吹雪**。密度用隨風漂的大尺度 noise 切成一陣一陣，左邊三分之一比較稀。主 pass 另外在腳下的坡面畫一縷一縷貼地掃過的細條紋（用坡面自己的日照／陰影上色）。storm 最強、overcast 少一點、clear／waiting 幾乎沒有。
- **雪煙**：每格從每個像素往**上風處**（隨目前風向，左或右）探 14 個深度樣本，找比較近的高稜線，沿下風方向用流動的條紋 noise 畫出被陽光照亮、從稜線拉出去的雪煙；風幾乎垂直時（無側風）就停了。
- **鑽石塵**：420 顆稀疏的冰晶，隨風慢慢漂、極慢地往下沉；每顆有自己的轉動節奏，晶面轉到對的角度時閃一下（四芒小亮點），顏色取主光（白天陽光、夜晚月光）。量 = 狀態的 `dust` × 早晨係數（07:30 前後最多、夜晚 0.6），clearing 最多、clear 次之、storm 沒有。
- **雲海跟著風漂**：雲團和高雲的位移是把風速「積分」起來的累積量（JS 每格加 速度×dt，當 uniform 傳進去），不是 時間×目前的風，所以風轉向時整片不會跳；各個 octave 往同一個方向、速度相近，平靜的速度但 10 秒內看得出來（強風時約 0.1 km／10 s），風轉向就慢慢倒著漂。
- **雲海的抗鋸齒**：每個像素算出自己在雲海上的足跡（掠射角越低越長），每個 billow octave 在波長小於約 2.5 個足跡時平滑地淡成平均值（預先濾波），遠處的雲團就不會疊成一排排階梯；往下找雲頂的步進用更多步、步長隨距離長大，步數用完還在雲上就當作打到（不會漏掉一整排）；第二層雲是實心的，薄邊下面不會透出一條遠山色的細線。
- **雲海的邊**：雲頂找到之後沿視線再取三段算密度積分（雲頂下方羽化、邊緣被 noise 撕碎，雲瀑上最明顯），不透明度＝1 − e^(−光學厚度)，所以掠過的雲頂和雲瀑的邊是半透明、會透光的（薄的地方加 wrap＋前向散射的亮邊）；最多兩層：薄邊後面還會再找一次雲，所以薄邊疊在後面的雲上，不會像剪影一樣露出遠山。

## 成本（2026-10-13 量測）

1920×1080，**全解析度**渲染＋FXAA（第四輪 2026-10-13 起；之前是半解析度 960×540 再放大 2×，單一取樣的山稜與雲團輪廓放大後變成 2 px 的階梯），RTX 2060 SUPER（`force_high_performance_gpu`，跟主程式一樣）。像素數上限約 2.1 MP（1920×1080），更大或 HiDPI 的螢幕會按比例降、交給瀏覽器放大；`?res=0.5` 這類網址參數可以強制比例（測試用）。`theme.bench(60)`：

| 狀態 | 中位數 | p90 |
|---|---|---|
| clear | 2.8 ms | 3.2 ms |
| overcast（雲瀑＋翻騰） | 3.8–4.1 ms | 4.1–4.4 ms |
| storm（翻騰＋雲瀑＋風吹雪） | 4.2–4.3 ms | 4.5–4.7 ms |
| waiting＋5 個營地 | 2.8 ms | 3.1 ms |
| 夜晚 storm＋3 個營地 | 4.2 ms | 4.6 ms |

（第八輪 2026-10-13 重量。**地形、帳篷、天空、風吹雪、鑽石塵、等你星是全解析度；雲海是半解析度**：另一個 pass 在 1/2 × 1/2 的畫面算雲海（預乘的散射光＋穿透率，RGBA16F，再加一張「這個雲是對著哪個地形深度算的」），全解析度 pass 用雙邊（深度感知）上採樣合成——四個最近的雲樣本依雙線性權重 × 地形深度相符程度加權，沒有一個相符時取深度最接近的那個——所以雲在前山、主峰、帳篷邊緣保持銳利、不暈開，軟的雲邊照樣是軟的；抖色在合成之後才加。之前雲海全解析度時 storm 是 10.8–11.0 ms。）

- 啟動時完整 bake（深度＋屬性，全解析度）約 480 ms（一次性；第五輪把深度 march 的步長縮小，避免穿過陡的刃脊）；之後重 bake 屬性一條掃描帶中位數約 1.5–1.8 ms（`theme.benchStrip()`），連續重 bake 時 rAF 間隔中位數 16.7 ms、p99 17.9 ms、最大 25.9 ms（不卡）
- 第一次啟動（shader 快取是空的）D3D 編譯約 17 s（主 pass 約 7 s、雲海 pass 約 1.8 s、屬性 pass 首次繪製約 5 s；營地迴圈和帳篷的 march 都收成不展開的單一呼叫點，不然主 pass 會到 21 s），之後有快取就很快；每個重的函式都收成單一呼叫點（迴圈＋`uOne`）就是為了壓這個時間
- `wpPause(true)` 和 `document.hidden` 都會停掉渲染

## 調整筆記

- 顏色全部是線性空間，最後過 ACES ＋ gamma，再加每個通道獨立的三角分布抖色（±1 LSB，每個像素固定、不閃）——天空、雲海、夜空的平滑漸層在 8 bit 輸出和放大 2× 到螢幕之後都不會出現色階。平滑漸層都是主 pass 即時算的，沒有經過 8 bit 的中間貼圖。
- `theme.CONFIG.clockHours`（0–24）固定時間；`theme.applyState(name)`／`requestState(name)`；`theme.setSessions([...])` 覆寫營地；`theme.rebake()` 重 bake 屬性、`theme.rebake(true)` 連深度；`theme.probe(x, y)` 讀某個螢幕點的 G-buffer。
- `theme.CONFIG.debugView`：1 = 素模（只看地形形狀）、2 = 雪的分布、3 = 岩紋／溝槽。`theme.CONFIG.skip = 'snow'`／`'bake'`／`'main'` 可以關掉某個 pass 量成本。
- 按鍵（預覽時）：1–5 切狀態、`d` 開除錯資訊。
